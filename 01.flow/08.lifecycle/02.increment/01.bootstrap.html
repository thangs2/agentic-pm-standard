Feature increment bootstrap — MVP → waves

Scope: End-to-end SDLC for a new function — Plane A (governance) → Plane B (dev factory) → Plane B′ (QC execute) → Plane C (human ship). Same domain_slug tree extends on each wave.

Not Plane A only: Stages 7–8 and closure 9 are Plane B; scenario execution is Plane B′; Story Done / PR / release are Plane C (agent never completes C).

Working copy (optional): {wbs}/01.features/{nn}.{domain_slug}/00.increment-bootstrap.md — tick progress; canonical law stays this doc + pre-flight matrix.

0. When to use

Situation Use
New feature, MVP, domain increment Full checklist — all planes over time
Single bug in one service Bug class + one task packet — Plane B slice only
Docs-only shard edit Plane A rows for that stage only
QC execution only Plane B′ + matrix — after qualified DEV Done

4. Eight product stages × delivery plane

Stage Name Plane Output Gate evidence
1 Requirements A requirements tree Intake A–H
2 Analysis A business-process pack AC + case catalog
3 QC design A quality-control folder SCN ↔ case_id
4 API & interface A API pack, C4, design trace Contract or OPEN
5 Data design A data-model + schema data-sync law
6 BIP/FIP / WBS A plan task packet, module pack READY / READY-SPLIT
7 Test spec (RED) A plan + B execute red-tests, nfr spec RED before GREEN
8 TDD implement B code + verify build PASS; anti-patterns 0 CR/HIGH
3′ QC execute B′ matrix runs, E2E/NFR QC gates
9 HIL & closure B HIL → C tracker HIL, delivery DoD human-in-review

Design trace: N/A for API-first domains — must not block stage 6 READY when HTTP + AC bound.

6. File checklist by group (summary)

6.1 Governance — Plane A

File Done when
domain-registry row slug unique
00.intake.md A–H pass or OPEN
00.domain.md bounded context
epic 01.sdlc-delivery-lifecycle.md “read next” links work
epic pre-flight filled stages 1–9 not BLOCKED for claimed complete
epic go-nogo filled Leader before wave cut

6.2 Requirements — stage 1

BRD → PRD → FRD → SRS — each with min content per template; FR/SRS ids trace to US.

6.3 Analysis — stage 2

Spine covers all US; full case catalog (H/E/F); flows per US; scenarios ↔ case_id.

6.4 Architecture — stages 4–5

C4 L0–L3 with diagrams; API shards; data-model; optional workflows/ops.

6.5 WBS — stage 6

Feature · epic · story · work-package · task · BIP · slice go-nogo · trace matrix row.

6.6 Plane B — stages 7–8

RED spec · atomic subtasks · code · topology if events · verify log · HIL.

6.7 Plane B′

Matrix execution · NFR evidence · QC HIL.

6.8 Plane C

DoD · code review · release gate · Story Done (human).
