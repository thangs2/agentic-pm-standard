    06 — Classification vocabulary and PM gate

    Purpose

    Exact classes, reason codes, Drive folders, Jira workflow, and who commits after classify. The trust ladder (auto-Ready vs bounce vs exception) is 24. Rubric A–G is 07 / 08.

    Amateur gate: two buckets (good / bad) and the TDM is the queue.
    Elite gate: typed exit, named next actor, SLA only on REWORK, park without guilt, P0 is not a story, commercial is not a rubric fail.

    1. Classes (closed set)

    One class per artifact. If two fire, take precedence (section 3), keep the other codes on the envelope.

    Lane Class Meaning Next actor Wait TDM?
    Quality VERIFIED A–G / hierarchy pass Auto Ready / /verified or PM if exception flags Only if exception
    Quality REWORK Fixable hole; reason codes required Sender + SLA 24–48h No
    Quality SPIKE Unknown how on purpose; timeboxed discovery Pod or BA, clock on the ticket No (PM only if spike > budget)
    Safety QUARANTINE PII, malware, unreadable, secret leak Security / DPO — no RAG Yes (legal), not as DoR
    Safety REJECT Wrong artifact, spam, not a requirement Close / /reject No
    Safety DUPLICATE Same ask as an existing key Link canonical + close this one No (PM if dispute which is canonical)
    Truth CONFLICT Two SoT disagree PM / human picks canonical Always
    Portfolio DEFER Valid work, wrong now (WIP, date, unfunded) Backlog / /park — no sender SLA No
    Portfolio CHANGE Mid-cycle insert into a loaded sprint Swap equal size or wait — Lead if conflict Yes for swap
    Portfolio TRADEOFF Two depts, one slot (CS vs Fraud vs Pay) Lead + PM Always
    Live INCIDENT Sev / live breakage War room (pod + on-call). Not A–G intake Inform, do not Ready as a feature
    In-flight BLOCKED_EXT Quality OK; waiting another team / vendor Status Blocked — do not un-Ready AC Escalate if needed-by missed
    Exit DONE_FAIL Marked Done without evidence Reopen / In Review — pod owns the hole Sample, not a queue

    Aliases already used in cases (do not mint a second class):

    Written in a case Canonical
    needs-deps 17 reason missing-deps under REWORK
    needs-ac 32 reason missing-ac / verbal-ac + Jira status Needs_AC
    design-drift 13 reason under CONFLICT
    done-not-done 21 class DONE_FAIL + reason done-not-done
    orphan 35 orphan-subtask
    scope-gap 20 reason under TRADEOFF or DEFER (commercial), not REWORK

    VERIFIED is a quality class, not a TDM queue item.

    2. Precedence (classifier must not flip a coin)

    flowchart TB
  In[Artifact in] --> S{Safety?}
  S -->|PII / unreadable / secret| Q[QUARANTINE]
  S -->|spam / wrong type| RJ[REJECT]
  S -->|same as existing key| DUP[DUPLICATE]
  S -->|no| L{Live Sev?}
  L -->|yes| INC[INCIDENT]
  L -->|no| T{Two SoT?}
  T -->|yes| CF[CONFLICT]
  T -->|no| P{Portfolio?}
  P -->|two depts one slot| TO[TRADEOFF]
  P -->|insert vs sprint goal| CH[CHANGE]
  P -->|right work wrong time| DF[DEFER]
  P -->|unknown how on purpose| SP[SPIKE]
  P -->|no| G{A-G / layer?}
  G -->|fail| RW[REWORK]
  G -->|pass| V[VERIFIED]
  V --> X{Exception flags?}
  X -->|yes| PM[commit_path pm]
  X -->|no| Auto[commit_path auto]

    After Ready: dep slip → BLOCKED_EXT. Fake Done → DONE_FAIL. Pod cannot execute → REWORK + bounce-from-pod to sender (45).

    untrusted-author New dept / dropped from ladder 24 Exception — pm

    done-not-done Done, no evidence 21 DONE_FAIL
    p0-sev Live breakage INCIDENT

    Do not invent free-text codes in production. If a new failure repeats twice, add it here in a retro — that is how the vocabulary stays a SoT.

    5. Drive stages (folders)

    flowchart LR
  I["/intake"] --> C["/classified"]
  C --> RW["/rework/{reason}"]
  C --> Q["/quarantine"]
  C --> PR["/pm-review"]
  C --> PK["/park"]
  C --> SK["/spike"]
  C --> V["/verified auto if policy"]
  PR --> V
  PR --> X["/reject"]
  RW -->|sender fix| I

    Move into /verified: auto if A–G + cites + confidence + trusted author and no exception flags; else /pm-review.
    DEFER → /park (not /rework). SPIKE → /spike. QUARANTINE never feeds RAG. AI may propose suggested_folder in JSON. RAG ingest after /verified.

    6. Jira stages (statuses or labels)

    If you cannot change workflow, use labels:

    ai:intake ai:needs-ac ai:needs-scope ai:needs-context ai:pm-review ai:ready ai:ready-blocked-ext ai:auto-ready ai:defer ai:spike ai:change ai:tradeoff ai:incident ai:duplicate ai:done-fail ai:quarantine

    Preferred statuses:

    stateDiagram-v2
  [*] --> Intake
  Intake --> Needs_AC: REWORK assign sender
  Intake --> Needs_Scope
  Intake --> Needs_Context
  Intake --> Spike
  Intake --> Parked: DEFER
  Intake --> Ready: auto-Ready policy
  Intake --> PM_Review: exception
  Intake --> Incident: live Sev
  Needs_AC --> Intake: sender fixed, re-score
  Needs_AC --> Ready: auto after re-score
  Needs_AC --> PM_Review: bounce≥2 / dispute / SLA miss
  Spike --> Ready: eval/design exists
  Spike --> Parked: spike expired
  Parked --> Intake: date / WIP opens
  PM_Review --> Ready
  PM_Review --> Needs_AC: bounce to sender
  PM_Review --> Parked

  Ready --> InProgress: pod pull
  InProgress --> Needs_AC: pod-bounce to sender
  InProgress --> Done: evidence
  Done --> InProgress: DONE_FAIL reopen

    AI never sets In Progress or Done (01).

    10. Human-in-the-loop sequence

    sequenceDiagram

  participant Board as Jira/Drive
  participant S as Sender
  participant PM
  participant Pod
  participant Lead

  else REWORK
    AI->>Board: Needs_AC + assign sender
    Board->>S: reason codes + SLA
  else DEFER or SPIKE
    AI->>Board: Parked or Spike

    AI->>Board: label incident

  end
