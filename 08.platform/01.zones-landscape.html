00 — Overall landscape

One map of the AI TDM operating system: zones, components, in / out. Detail lives in mapping 01, architecture 01–09, cases 10–27, edges 30–52. This file is the picture you hold in your head.

Law (from 01): AI reads, classifies, drafts. Green auto-commits. Red returns to sender. PM owns exceptions + the rule. Nucleus is never the source of truth.

Zones are a dataflow, not an always-on BPMN. A BA creating a Jira ticket (Zone 1) does not run the nucleus until a trigger fires (§1b).

Cockpit is swappable. Diagrams below use Cursor as the default Zone 3. Company-Claude map: §3b and 02b. Zones 1, 5, 6 stay the same.

1. Zones (left → right)

Work enters on the left, gets judged in the center, lands on the right. People sit outside the nucleus: senders on the source side, pods and leads on the destination side.

Each zone is a vertical column. Happy path is left → right. Red bounce and quarantine curve back to the sender. Pod pulls Ready (never waits TDM); the Dept Head gets the status pack.

Clock vs cockpit

Phase (24) What “cron” means Who runs Cursor required?
0 Calendar / reminder (“Monday 9:00”) TDM types /scan-blocked or /classify Yes — HITL session
1+ Real job (GitHub Actions, LangGraph, cloud scheduler, mu-agenda) Runner wakes the same MCP + policy No — headless

Cursor is not a cron daemon. Laptop closed → Phase 0 scan does not run. Do not install a “cron app” until JQL/skills are boring (23: manual ≥ 3 weeks before LangGraph).

Four wake-ups

ID Trigger Typical artifact Then Not
A Webhook / folder watch Jira create/update (11); Drive /intake (10); Slack packet (22) Classify now Meet → Ready (12)
B Calendar + cockpit Weekly blocked/risk (23); status pack (16) Draft + breakpoint — TDM sends Auto-Slack the company
C Scheduler (later) Same as B, plus daily Intake sweep Same MCP job as A/B, no IDE Cursor-as-clock
D Manual /classify Paste, exception, Phase 0 calibrate Same gate Silent bulk Ready

Re-score is A again: sender/BA fixes Needs_AC → Jira updated → classify. That is how a BA ticket becomes Ready — not “create = Ready”.

Filter (job refuses)

Must be true Else
Status Intake / label ai:intake (or the case’s entry status) Skip In Progress / Done — AI never sets those (06)
Readable via MCP 50 — do not guess
Right case File → 10; Jira graph → 11; Meet → 12 Intake stubs only; Sev ping → 27 not A–G
Write Ready only if 24 policy Comment + labels always; Ready is apply-policy

6. Three traffic patterns (the actual loops)

A — Green (happy path)

Sender / system → Zone 1 → trigger + filter (§1b) → MCP in → Nucleus + RAG cite → A–G pass + policy → auto Ready / /verified → Pod pulls. TDM is not in the loop. Sample later.

sequenceDiagram
  participant S as Sender / Drive / Jira
  participant T as Trigger A/B/C/D
  participant MCP
  participant N as Nucleus
  participant G as Gate
  participant D as Destination
  participant P as Pod

  S->>T: artifact sitting
  T->>MCP: webhook / calendar+HITL / job / manual
  MCP->>N: bytes + metadata
  N->>N: RAG cite + A-G
  N->>G: VERIFIED + policy OK
  G->>D: auto Ready / /verified
  P->>D: pull
  Note over N,G: TDM not here

B — Red (bounce to sender)

Missing A–G → Needs_AC assigned to sender + SLA. Re-score. Auto Ready if now green. TDM still not here unless bounce ≥ 2 / dispute / SLA miss.

sequenceDiagram
  participant N as Nucleus
  participant J as Jira
  participant S as Sender
  participant TDM

  N->>J: REWORK + reason codes
  J->>S: Needs_AC SLA 24.48h
  S->>J: fix
  Note over S,J: Trigger A — Jira updated
  N->>J: re-score
  alt green + policy
    J->>J: auto Ready
  else still red
    J->>S: still Needs_AC
  else dispute / bounce≥2
    S->>TDM: exception queue
  end

C — Yellow (PM exception)

P0, CONFLICT, PII, new author, low confidence, SoW gap → pm-review. TDM stamps or bounces. Then destination same as green.

Pods never wait on C to pull a green ticket sitting in Ready.

Plane Zone Example Wins a fight?
