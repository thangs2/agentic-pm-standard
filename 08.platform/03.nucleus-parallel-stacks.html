    02 — Nucleus and parallel stacks

    Purpose

    Pin the daily driver (Cursor nucleus) and the two parallel systems: Claude’s cockpit and a CodeGraph-class intelligence engine.

    Daily driver (canonical)

    flowchart TB
  subgraph nucleus [Canonical nucleus]
    Cursor["Cursor IDE<br/>orchestrator"]
    DS["DeepSeek v4<br/>reason + classify"]
    AM["AgentMemory MCP<br/>PM long-term memory"]
    CG["CodeGraph MCP<br/>AST / callers / impact"]
    MCP["MCP clients"]
  end

  Cursor --> DS
  Cursor --> AM
  Cursor --> CG
  Cursor --> MCP
    Piece Job Not the job
    Cursor Session, tool calls, file edits, human in the loop Source of truth
    DeepSeek v4 Rubric scoring, MoM structure, JSON drafts Silent commit
    AgentMemory Decisions, conventions, “how we run sprints”, pod vocabulary Replace Confluence
    CodeGraph Symbol graph, blast radius when tickets mention code Understand business AC
    MCP Typed read/write to Jira, Drive, Git, Figma / Penpot… Policy. Policy is PM gate

    Company claude.ai (web Project, not the same as Claude Code): full swap map in 02b.

    Parallel stack A — Claude (same shape, different cockpit)

    Use when you want a second model or a terminal-native agent. Same SoT. Same gate. Detail for company-Claude: 02b.

    flowchart LR
  CC[Claude Code] --> MCP2[Same MCP servers]
  Proj[Claude Projects / Memory] -.->|project files + prefs| CC
  MCP2 --> Jira
  MCP2 --> Drive
  MCP2 --> Git
    Claude piece Maps to
    Claude Code Cursor
    Claude Projects + Memory AgentMemory-like
    MCP in Claude Code Same MCP bus
    (gap) No native CodeGraph — pair with Sourcegraph or keep CodeGraph MCP

    Do not run two writers on the same Jira ticket in one session.

    Parallel stack B — CodeGraph-class (Sourcegraph)

    flowchart LR
  SG[Sourcegraph / SCIP index] --> Cody[Cody or API]
  CG[CodeGraph in-repo] --> Cursor
  Git[(GitHub / GitLab)] --> SG
  Git --> CG
    Engine Best when
    CodeGraph (this repo) Local, fast, Cursor-native
    Sourcegraph Multi-repo, enterprise GitLab/GitHub, precise find-refs at org scale

    PM uses either to answer: “If we change metric grain, what services break?” — then BA/dev still own the how.

    Optional siblings (not nucleus)

    Tool Role
    Windsurf Alternate IDE cockpit — same rule as Claude Code
    GitHub Copilot PR comments / in-IDE complete — not the operating system
    NotebookLM Doc Q&A sandbox — never canonical SoT

    Memory write policy

    flowchart TD
  Event[Decision in meeting / retro] --> Draft[AI draft memory card]
  Draft --> PM{PM OK?}
  PM -->|yes| AM[AgentMemory save]
  PM -->|yes| Conf[Confluence/Notion if org SoT]
  PM -->|no| Drop[Discard]

    AgentMemory stores how we work. Org SoT stores what was decided for the product. Duplicate the decision into Confluence when others must see it without Cursor.
