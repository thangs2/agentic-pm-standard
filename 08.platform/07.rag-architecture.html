05 — RAG architecture

Purpose

How the AI PM retrieves project truth without stuffing the whole Drive into one prompt. RAG = knowledge of this program. Fine-tune is out of scope (behavior/format only, later, almost never).

Collections (separate indexes)

flowchart TB
  subgraph collections [Vector / hybrid collections]
    C1[col_requirements<br/>PRD BRD AC packets]
    C2[col_meetings<br/>MoM transcripts cited]
    C3[col_decisions<br/>ADR + PM decisions]
    C4[col_jira<br/>issue snapshots]
    C5[col_design<br/>Figma / Penpot text + frames]
    C6[col_code_hints<br/>NOT full repo - pointers to CodeGraph]
  end

  Ingest[Ingest pipeline] --> collections
  Query[DeepSeek query] --> Router[Collection router]
  Router --> collections
Collection Ingest when Query when
requirements File in /verified (auto-policy or PM exception) Classify new docs, draft AC
meetings MoM approved “Who said X”, action follow-up
decisions After PM OK + Confluence Status, conflicts
jira Ticket created/updated Hierarchy, duplicates
design Figma / Penpot comment/gate Drift vs AC
code_hints Optional: file+symbol ids only Never embed secrets

Do not dump Git blobs into RAG. Use CodeGraph/Sourcegraph at query time.

Ingest pipeline

flowchart LR
  File[Canonical file / issue] --> Gate{/verified or system snapshot?}
  Gate -->|no| Skip[Do not ingest]
  Gate -->|yes| Clean[Strip PII / headers]
  Clean --> Chunk[Chunk by heading / ticket]
  Chunk --> Meta[Metadata: pod, sprint, source URL, version]
  Meta --> Index[Embed + BM25]

Unverified intake never enters col_requirements. It can sit in a volatile col_inbox with TTL 14 days if you must search drafts — default off.

Retrieve-then-generate

sequenceDiagram
  participant PM
  participant C as Cursor
  participant R as Retriever
  participant D as DeepSeek

  PM->>C: Is this PRD good enough?
  C->>R: hybrid search (title + pod + type=PRD)
  R-->>C: chunks + source URLs
  C->>D: rubric A-G — answer ONLY from chunks
  D-->>C: class + missing + citations
  C-->>PM: verdict

Citation law

Every AC line, every “who approved”, every date must carry:

plaintext
12
cite: {system, id, version or rev, loc}
example: Drive:fileId p.4 §Acceptance | Jira:OA-123 description | Meet:MoM-2026.09-10

No cite → cannot be VERIFIED. Class REWORK reason uncited-claim (38).

Query router

User intent Collections
Document quality requirements + meetings
Jira DoR jira + requirements
Status jira + decisions
Design drift design + jira
Code impact CodeGraph live, not RAG

AgentMemory vs RAG

AgentMemory RAG collections
Shape Few durable cards Many chunks
Example “Fraud pod hates Slack-assigned work” Full PRD text
Update PM save Ingest from SoT

Both can be wrong. Jira/Confluence/Drive win on conflict (14).
