04 — Departments, actors, and data flows

Purpose

Who produces noise, who consumes Ready work, who approves trade-offs. Maps to multi-department pods: CS, Marketing, Fraud, Payments + technical pods.

Actor catalog

Actor Wants Gives the system Must not
CS lead Faster triage, SLAs Messy requests, examples Prescribe SQL
Marketing Campaign dates Metric names, deadlines Silent sprint insert
Fraud Risk rules, alerts Thresholds, false-positive pain Unscoped “improve model”
Payments Breakage = P0 Incident context Skip DoR because urgent (still need thin AC)
BA / PO Clear backlog Draft stories, Figma / Penpot Skip DoR / skip sender bounce
Technical pod Pull-ready tickets How, estimates, CI Start from Slack; bounce to TDM instead of sender
Dept Head Honest status Priority calls Weaponize velocity
TDM (you) Flow + quality policy Exceptions, sample, escalate Become human router / click every Ready
Security / Legal PII, retention Blocks Ignored by RAG ingest

RACI for the AI PM loop

Activity TDM BA / sender Pod Dept lead
Capture / classify A (policy) C I I
AC quality / red fix A (rule) R C (pod-bounce) I
Auto-Ready apply A (policy) I I I
Exception stamp R C I I
Priority when conflict C C I A
How / estimate I C A/R I
Pull from Ready I I A/R I
Status label A C R (facts) I
Merge code I I A I

A = accountable, R = responsible.
